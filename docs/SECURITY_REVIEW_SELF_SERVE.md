# Self-serve adversarial review

Reviewed the binding tenant contract, plan sections 3–6 and 8, hostname attach documentation, and the existing onboarding, control registry, and edge server. Build-only review; no live systems or DNS were queried. The internal server, shared hostname normalizer, and portal are absent in this worktree. Their tests skip explicitly, so a green lane run is not evidence that their protections exist.

## Contract questions

1. Every non-GET requires a per-session CSRF token, including signup/login, but no anonymous CSRF bootstrap is specified. The test browser first calls `/api/me` and consumes any returned cookie/`csrf`. Specify the pre-authentication bootstrap and exact 403 error code. The suite currently checks the error shape without inventing a code.
2. The portal factory's `config` keys and invite mint export are unspecified. The helper uses `config.origin` and an object-form `generateInvite`, `mintInvite`, or `createInvite` with `dataDir`, email, optional tenant and limits. Read the merged invite implementation and adapt this one helper; absent exports skip visibly. Confirm whether invite-bound tenant IDs are honored or generated on redemption.
3. “Every awkward hostname” returning foreign-owner 404 conflicts with invalid syntax returning 400. Wildcards/IP literals cannot be owned; this suite rejects them at creation and checks valid owned names for exact foreign 404 responses. Define validation precedence on record routes, including raw dot-segment tenant paths.
4. Deleting one's losing pending claim should remove only that claim, without closing the active owner's tunnel. The suite asserts this interpretation of tenant-scoped DELETE. Confirm the behavior once another tenant activates.
5. Define trusted proxy addresses, accepted client-IP headers, rate-limit persistence/restart behavior, whether failed invites consume signup quota, and fixed versus sliding windows. Recovery tests advance a full window plus one millisecond.
6. Set the DNS timeout budget, precise five-hop convention, treatment of private CNAME targets, and public-suffix rejection source. The plan mentions public suffixes, while the dependency-free contract only gives hostname syntax and configurable reservations. The resolver-hang test permits 6.5 seconds, just beyond the specified five-second request budget.
7. Clarify activation-time versus continuous DNS proof, expiry cleanup of credentials, active-record `expires_at`/TXT retention, and crash consistency across the claim, credential and routing files. Current tests do not simulate process crashes between writes.

## Test and scan limitations

`node test/helpers/run-tests.js --lane` runs only this lane. `node test/helpers/run-tests.js` invokes `npm test` with temporary files inside the worktree, a DNS fake, external socket blocking, and remote-command interception for legacy tests. This preserves failures while preventing the existing DNS and SCP tests from reaching real services. It is not a general OS sandbox.

The name deny-list is data only. Legacy exceptions pin hashes and occurrence counts of reviewed matching lines, so new names in the same files still fail. One pre-existing deployment comment is pinned pending lane A removal, alongside legacy defaults and fixture tests. No new implementation path is exempt. Contract and plan documents are explicitly allowed. Sensitive files, symlinks, binary data and dependency trees are not opened by the scanner. The literal-hostname check is a lightweight source check, not a full JavaScript parser; dynamically assembled names still require review.

An in-memory HTTP stub demonstrates that the actual exact-error assertion rejects a leaking 200 response. Scanner self-tests inject every denied value and verify failure, including additions to an otherwise exempt legacy file. These checks validate the test machinery, not the missing implementations.
