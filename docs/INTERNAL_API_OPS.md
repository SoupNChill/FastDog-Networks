# Internal tenant API operations

The listener defaults off. To enable during a separately authorized deployment, configure `INTERNAL_ENABLED=1`, `INTERNAL_BIND=127.0.0.1`, `INTERNAL_PORT=8789`, and a separately generated `PORTAL_KEY` of at least 32 characters that differs from `AGENT_TOKEN`. Provision secrets outside the repository in a mode-600 service environment file; do not place them in command arguments or logs. Restart the edge after configuring the portal with the same portal key. Invalid keys or a non-loopback bind cause startup to fail before listeners start.

Configure `ATTACH_TARGET`, `ALT_ATTACH_TARGET`, `EDGE_PUBLIC_IP`, `DATA_DIR` and `RESERVED_SUFFIXES` for the installation. `RESERVED_SUFFIXES` is a comma-separated list of names and suffixes. When absent, the final two labels of each configured attach target are reserved, plus localhost, local, lan, internal, test, invalid and example. This is conservative for multi-label public suffixes; explicitly configure the registrable domains in that case. Attach targets themselves remain reserved even when overriding the list.

The unauthenticated loopback checks are `GET /health` and `GET /tls/ask?domain=app.example.com`; both also accept the `/internal/v1` prefix. Every tenant operation is under `/internal/v1/tenants/:tid/hostnames` and requires the `x-fastdog-portal-key` header. The operator key cannot call this API. TLS ask returns an empty 200 only for an active tenant claim or an active legacy attachment. Configure Caddy's on-demand TLS ask separately; this build does not change running TLS configuration.

Claims, credentials and host mappings use the existing atomic JSON writer. Claim and credential files are mode 600; tokens are hashed at rest. Back up the data directory using the existing restricted backup process. Use a single edge writer. Verify and rotate limits are in memory and reset when the edge restarts. Request bodies are limited to 16 KiB; requests time out after five seconds, with an incomplete body reported as `invalid_json` if a response can still be sent. DNS passes have a 3.5-second deadline and return `dns_timeout` checks. Internal logs contain only method, route template, status and duration.

Public control requests under `/_fastdog/dns`, reads of agents/routes/metrics, and route reload now require the operator token in `x-fastdog-token` or a JSON `token` field. Configure the operator token explicitly; the existing development fallback remains for compatibility with the operator and billing services. The operator UI already supplies the header. Update any external scripts to supply it without putting the token in a URL.

Rollback: unset `INTERNAL_ENABLED` and restart the edge. This disables only the internal listener; persisted active hosts and credentials remain, and control-plane authentication remains enabled. Revert the build separately if those behaviors also need to be rolled back. Nothing in this document has been deployed.

## Active-claim re-checks and operator recovery

Re-checks default off. Set `RECHECK_ENABLED=1` alongside `INTERNAL_ENABLED=1` and restart to schedule a run every six hours (the first run is six hours after listening). Disabling either flag stops scheduled re-checks. Each active or suspended claim gets at most one DNS lookup per run, with a 3.5-second deadline: direct CNAME proofs check CNAME against the configured attach targets; A-record and chained-CNAME proofs check a recursive A answer against `EDGE_PUBLIC_IP`. There is no chain walk, fallback lookup or TXT lookup during a scheduled run. If the routing record type changes, use explicit verification below to refresh the proof method.

The claim stores `recheck_failures` and `last_rechecked_at`. Success resets the consecutive failure count; three failures suspend the claim, remove its tunnel mapping, close its tunnel and stop its credential validating. Suspended claims do not expire and still count toward the tenant limit. The claim and credential remain stored. A later successful run restores the mapping and the same credential, provided no other tenant is active for that hostname. Suspended API records expose no TXT challenge; TLS ask denies them.

Operator override / immediate re-activation: restore routing and the original ownership TXT record, then use the authenticated internal `POST /internal/v1/tenants/:tid/hostnames/:hostname/verify` endpoint through the existing secure operator process (keep the portal key out of command arguments and logs). This checks both proofs immediately, clears the failure count and restores the existing credential without issuing a replacement. It refuses activation if another tenant now owns the hostname. For automatic recovery without the TXT proof, restore the original routing and wait for the next enabled re-check. Do not delete/re-create the claim or edit credential files. If the retained token was lost, rotate it after re-activation.
