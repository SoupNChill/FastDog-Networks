# Billing scaffold (Stripe test mode only)

The public `/pricing` page shows placeholder Starter ($9/month) and Pro ($29/month) plans. Checkout uses Stripe test mode only. No real charges, DNS changes, or onboarding payment gate are part of this scaffold.

1. Never put live keys in this repository. Copy `.env.example` to `.env` and set `STRIPE_SECRET_KEY=sk_test_...` and `STRIPE_PUBLISHABLE_KEY=pk_test_...` from Pete's Stripe test account. The server uses the secret key; the publishable key is reserved for a future browser integration. Optional `STRIPE_PRICE_STARTER` and `STRIPE_PRICE_PRO` must be test Price IDs. Without them Checkout creates the displayed monthly test prices inline.
2. Set `STRIPE_SUCCESS_URL` and `STRIPE_CANCEL_URL` if the default localhost URLs are unsuitable. The success URL must end in `?session_id={CHECKOUT_SESSION_ID}`. The defaults use `http://localhost:8787/_fastdog/billing/success?session_id={CHECKOUT_SESSION_ID}` and `http://localhost:8787/_fastdog/billing/cancel`.
3. Run `npm install`, then load the variables from `.env` into your shell and run `npm start`. Open `http://localhost:8787/pricing`. The app itself does not read `.env` automatically. With no test key, Checkout returns `set_test_keys` and the page shows a clear message.
4. In another shell run `stripe listen --forward-to localhost:8787/_fastdog/billing/webhook`. Put the CLI's `whsec_...` value in `STRIPE_WEBHOOK_SECRET`, then restart the edge. The webhook accepts signed `checkout.session.completed` events only. The success route also retrieves the session from Stripe. Either path marks a locally recorded, completed, paid test session as `paid_test` in `DATA_DIR/billing-accounts.json`; sessions are tracked in `DATA_DIR/billing-sessions.json`. This is a payment stub, not an access gate. Use `GET /_fastdog/billing/status?zone=example.com` with `x-fastdog-token: <AGENT_TOKEN>` to inspect it.
