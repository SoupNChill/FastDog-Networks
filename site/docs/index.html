Put your website on FastDog.

Four steps: add your address, add two DNS records, connect your server, then check that it’s live. Your app keeps running where it is.

For AI assistants: the same guide in plain text is at /llms.txt.

How it works

  1. Visitors type your address. A CNAME record at your DNS provider sends them to FastDog’s edge.
  2. The edge answers over HTTPS with a certificate it gets for you automatically.
  3. A small program on your server (the agent) keeps one outbound connection open to the edge. Each request travels down that connection to your app.

Why no ports? The agent dials out, the way a browser does, so you don’t open ports, change your firewall or reveal your server’s IP address.

1. Add your website address

In the portal, enter the address people will use, such as app.example.com. Use a subdomain: most DNS providers can’t put a CNAME on a root domain like example.com. If yours supports ALIAS, ANAME or CNAME flattening, that works too.

2. Add two DNS records

The portal shows both records with the exact field names for Cloudflare, Namecheap, GoDaddy, Route 53, Porkbun and others.

  • CNAME on your address, pointing at the attach target the portal shows. It sends visitors to FastDog.
  • TXT on _fastdog-challenge. plus your address, with the value the portal shows. It proves you own the domain, so nobody else can connect it.

Why two records? One routes traffic and one proves ownership. Keep both in place; FastDog may re-check them.

Cloudflare: use grey cloud. Set Proxy status to “DNS only” (grey cloud). Grey cloud means Cloudflare only answers DNS and visitors go straight to FastDog. Orange cloud (Proxied) puts Cloudflare in the middle, which hides your record from our check and stops your HTTPS certificate.

DNS changes can take a few minutes, sometimes a few hours, to spread. Press Check in the portal once they’re saved.

3. Connect your server

On the Server page, enter where your app listens on that server, such as http://127.0.0.1:3000, then press Get my connect command. Run the command on that server. Docker is recommended (no sudo needed); the Linux systemd installer, macOS and Windows commands are also offered.

The command contains a private key and is shown once. Don’t paste it into chats, tickets or logs. Getting a new command replaces the old key and closes any current connection until you run the new one.

4. Check it’s live

The Status page shows a big Live or Not live, when it was last checked, your certificate’s expiry, whether the agent is connected and your app is answering, requests over the last 24 hours, typical response time, and bot-check counts in shadow mode (counted only, nothing blocked). Test it loads your home page through FastDog and shows the status code, time and certificate.

Using an AI assistant

On the Server page, press Create prompt under “Copy prompt for your AI assistant”. The prompt includes a connect token that:

  • works for one website address only,
  • can only read that address’s connection status and get its connect command once,
  • expires after one hour, and can be revoked at any time from the same page.

The assistant sends it as Authorization: Bearer <token> to two endpoints on the portal:

  • GET /api/connect/v1/hostname: the address, token expiry, and agent.connected / agent.origin_reachable.
  • POST /api/connect/v1/command with {"origin": "http://127.0.0.1:3000", "platform": "docker"} (or "linux" for the systemd installer): returns the connect command once. Origins must be local or private addresses with a port (link-local 169.254.0.0/16 and fe80::/10 are refused). Docker group access is root-equivalent: use Docker only if you already have it without sudo.

Tokens are never accepted in a URL. Your password and sudo prompts stay with you.

An assistant that holds an API key (see below) can do the whole job from scratch:

  1. It adds the website address and shows you the two DNS records. It normally can’t add them itself, so add them at your DNS provider (on Cloudflare, “DNS only”, grey cloud).
  2. It checks every 30 seconds. “Not found yet” results before the records exist are normal. A pending address is reserved for 24 hours.
  3. It asks which port your app uses and fetches the connect command, using Docker by default. It first checks that docker info works without sudo; if it fails with permission denied, add your user to the docker group, or use the systemd installer (platform "linux"), which needs sudo, so you run it yourself. The Docker command needs no sudo, so you can approve the assistant running it, but it contains the agent’s private token, so the assistant must not print it. It saves the response with curl --create-file-mode 0600 -o /absolute/path/fastdog-connect.json ... (needs curl 7.75 or newer, so the file is private without umask or chmod; with older curl run umask 077 first), runs the command from the file without echoing it, deletes the file and checks docker ps --filter name=fastdog-agent. The command uses --network host, so 127.0.0.1 reaches your app (on Docker Desktop for macOS or Windows use host.docker.internal instead), and running it again replaces the old agent. Each address allows 3 new commands a day; a new command replaces the old connection.
  4. It polls the status until it says live, then opens your address. If the status stays on “no HTTPS certificate”, HTTPS isn’t ready yet: wait about 10 minutes, and contact support if it persists beyond 30.

The connect-token prompt only exists after the address is verified and only covers the connect step; an API key covers everything. Assistants with a command allowlist refuse commands that expand a secret like $KEY, so you save the Authorization header once to a private file yourself (or approve the assistant running it once): mkdir -p ~/.config/fastdog && (umask 077; printf 'Authorization: Bearer %s\n' '<paste key>' > ~/.config/fastdog/<hostname>.header). Name the file per hostname so credentials never overwrite each other. The leading space keeps the command out of shell history in most shells (HISTCONTROL=ignorespace); otherwise delete it from your history. The assistant then uses curl -H @/absolute/path/<hostname>.header and never curl -v or --trace, which print the Authorization header. When setup is done, delete the file and revoke the key if you no longer need it; a connect token’s file can be deleted right after connecting. If you already told it your app’s port, it won’t ask again. The full machine-readable guide is /llms.txt.

API keys

For scripts and AI assistants that do more than one connection, create an API key on the portal?s API keys page (every paid plan). You choose what it can do, optionally which websites it covers, and when it expires (30 days by default, 90 at most). It is shown once, stored only as a hash, and you can revoke it at any time. Changing your password ends all your keys.

  • hostnames:create: add a website and check its DNS records.
  • status:read: read the live status of your websites.
  • connect: get a connect command. Each one replaces the current server connection.

Removing a website is only possible in the portal. Send the key as Authorization: Bearer <key>, never in a URL.

  • POST /api/v1/hostnames with {"hostname": "app.example.com"}: adds it and returns the two DNS records.
  • GET /api/v1/hostnames/<hostname>: the address, its state and the records still to add.
  • POST /api/v1/hostnames/<hostname>/verify: checks the DNS records.
  • GET /api/v1/hostnames/<hostname>/status: the same data as the Status page.
  • POST /api/v1/hostnames/<hostname>/connect with {"origin": "http://127.0.0.1:3000", "platform": "docker"} (or "linux"): returns a connect command.

Limits: 60 requests a minute per key, 5 new keys an hour, 10 active keys per account. Every use is logged with the key?s name, never the key itself, and the portal shows when each key was last used.

Troubleshooting

“We haven’t seen your records yet”
Wait a few minutes and check again. Make sure the TXT name starts with _fastdog-challenge. and your provider didn’t add your domain twice.
“Your record is proxied by Cloudflare”
Switch the CNAME to DNS only (grey cloud).
Agent connected, but your app isn’t answering
Start your app, or fix the address you entered. The Linux Docker command uses host networking, so 127.0.0.1 works; on Docker Desktop 127.0.0.1 is the container itself, so use host.docker.internal.
Not live: no certificate yet
HTTPS isn’t ready yet. Make sure DNS is verified and the agent is connected, wait about 10 minutes, then refresh Status or press Test it. If it still says no certificate after 30 minutes, contact support with your address.
